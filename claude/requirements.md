# Requirements

## 1. Goal

Deploy the ColourLock measurement instrument as a web application that
(a) presents the published study results, (b) scores user-supplied images
with the exact study metrics, and (c) optionally generates new images with the
study's models and scores them.

## 2. Users

| User | Needs |
|---|---|
| Reviewer / reader of the paper | Inspect the dataset and results behind each claim, with provenance |
| Researcher | Score their own generated images with the same metric definitions |
| Demo visitor | Try a live generation and see how far the colour drifts |
| Maintainers (us) | Reproducibility, low cost, clear provenance per result |

## 3. Functional requirements

### FR-1 Study explorer (priority: must, no GPU)
- FR-1.1 List results per model × colour × prompt style: mean ΔE00 to target (accuracy), consistency (mean ΔE00 to group centroid), QC pass rate, n. Cells with n < 10 (most of SDXL, see D-16) must be visibly marked low-n/unreliable, not rendered as if comparable to n≈24–29 FLUX cells.
- FR-1.2 Show H1, H2 and H3 results with test name, statistic, p-value and effect direction, exactly as reported in the paper.
- FR-1.3 Browse individual study images with filters (model, colour, style, QC pass/fail) and show each image's manifest record (seed_used, metrics).
- FR-1.4 Show the methodological disclosures (see research-context.md §6) on every results page.
- FR-1.5 Link to the Zenodo DOI once published.

### FR-2 Score an image (priority: must, CPU only)
- FR-2.1 Accept PNG (preferred) or JPEG upload, max 10 MB, max 2048 px on the long side.
- FR-2.2 Accept a target as one of the 8 study targets or any `#RRGGBB` hex.
- FR-2.3 Return: target Lab, sample Lab, ΔE00, flat_p95_de, QC pass/fail with the threshold used, sample chroma, reference chroma, chroma delta, kept_pct (legacy), package version.
- FR-2.4 Warn when the upload is JPEG (compression affects colour measurement) or carries a non-sRGB ICC profile.
- FR-2.5 Scoring must be deterministic: same image + target → identical output.

### FR-3 Generate + score (priority: should, GPU)
- FR-3.1 User chooses model (FLUX.1-schnell or SDXL), target colour, prompt style (A–E), and optionally a seed.
- FR-3.2 Prompts are built by the same template code as the study. Free-text prompts are optional (phase 3+) and must pass the CLIP 77-token check.
- FR-3.3 Generation parameters match the study (see specs.md §4) unless explicitly marked "off-study" in the result.
- FR-3.4 Asynchronous: request returns a job id; client polls or subscribes for status.
- FR-3.5 Each result stores model id, revision sha, precision, seed, prompt, negative prompt (SDXL), steps, guidance, resolution, and scores.
- FR-3.6 Results are clearly labelled as single images: consistency and hypothesis tests are not shown for them.

### FR-4 Provenance endpoint (priority: must)
- Expose model ids, revision shas, precisions, QC threshold, package version, and git commit of the running service.

## 4. Non-functional requirements

| ID | Requirement |
|---|---|
| NFR-1 Parity | The `colourlock` package run on the 2,560 saved study images reproduces every notebook manifest metric within 1e-6 absolute. |
| NFR-2 Reproducibility | Same model, revision, precision, seed and prompt on the same GPU type produces the same image (FLUX determinism was verified in notebook Step 4c). |
| NFR-3 Cost | Study explorer and scoring run without a GPU. The GPU worker scales to zero when idle. |
| NFR-4 Latency | /score p95 < 2 s. /generate is async; a cold start may take minutes and the UI must say so. |
| NFR-5 Security | HF_TOKEN only in the secret store. Upload validation (type, size, dimensions, decompression-bomb guard). Rate limit /generate per client. |
| NFR-6 Observability | Structured JSON logs, job timing (queue wait, load, generate, score), GPU peak memory per job. |
| NFR-7 Licensing | Terms of service pass through the SDXL CreativeML OpenRAIL++-M use restrictions. FLUX.1-schnell is Apache-2.0 (gated repo). |

## 5. Out of scope

- Training, fine-tuning or converting any model.
- Pantone or physical colour references (the study uses CSS3/X11 digital values).
- Running both models concurrently on one GPU.
- Computing hypothesis tests on user data.
- User accounts in phase 1–3 (anonymous with rate limits).

## 6. Acceptance criteria per phase

- **Phase 1 (package):** parity test green on all 2,560 images; unit tests on synthetic swatches green; notebook imports the package and still produces the same tables.
- **Phase 2 (API + explorer + scoring):** FR-1, FR-2 and FR-4 are implemented and deployed on CPU hosting.
- **Phase 3 (generation):** FR-3 implemented; an SDXL image generated by the service with a study seed matches the study image's metrics.
- **Phase 4 (release):** Zenodo DOI linked; disclosures visible; load test on /score passes NFR-4.
